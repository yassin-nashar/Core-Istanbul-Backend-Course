# Solution guide

`firebase.ts` initializes the modular app and Firestore. `notes.service.ts` keeps data access separate from UI: `addDoc` creates a generated ID, `getDocs` reads the `notes` collection, `updateDoc` changes only editable fields, and `deleteDoc` is the stretch operation. `serverTimestamp()` is generated by Firestore, preserving `createdAt` during updates. Validation trims and rejects empty values before network calls. Rules require authentication in cloud deployments. Unlike Prisma, Firebase uses the client SDK directly and Firestore collections/documents instead of a server-side ORM.
